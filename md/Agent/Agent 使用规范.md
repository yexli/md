# Agent 使用规范

## 每次接手任务时

1. 读 `md/` 下的相关文档，不要凭印象改
2. 确认改动落在哪个模块，避免顺手重构无关代码
3. 改完自己跑一遍，不要交给别人验证

## 代码要求

- 结构清晰，一个文件只做一件事
- 命名说人话，避免 `data`、`item`、`handle` 这类空词
- 不写「以后可能用到」的抽象层
- 注释只解释**为什么**，不复述代码在干什么

## 输出要求

| 场景 | 应该输出 |
| --- | --- |
| 完成一个功能 | 改了什么文件 + 怎么验证 |
| 遇到冲突 | 冲突原因 + 最小修改方案 |
| 发现方案问题 | 直接说问题，不要顺着往下做 |

## 禁止事项

- ❌ 一次性重构整个项目
- ❌ 引入方案之外的大型依赖
- ❌ 删除现有文档或示例文件
- ❌ 把 `/md/` 的内容搬进数据库或接口
