# 架构设计

## 一条链路

```text
/md/*.md
   ↓  Vite glob 导入（构建 / 启动时读取）
文档索引  docs[]
   ↓  按目录分组
菜单树 + 搜索索引
   ↓  用户点击
Markdown 渲染  →  安全过滤  →  右侧阅读区
```

没有中间层，没有数据库，没有接口。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `src/main.js` | 入口，引入样式并启动应用 |
| `src/App.js` | 装配各个模块，管理 URL 状态与移动端抽屉 |
| `src/utils/documentLoader.js` | 读取 `/md/`、提取标题、构建目录树 |
| `src/utils/markdownRenderer.js` | Markdown → 安全 HTML，处理相对路径 |
| `src/utils/wikiUrl.js` | `?doc=` 参数的读写 |
| `src/components/sidebar.js` | 左侧目录树、高亮、折叠 |
| `src/components/search.js` | 标题 + 正文搜索 |
| `src/components/markdownViewer.js` | 内容渲染、代码复制、站内链接跳转 |
| `src/components/copyButton.js` | 复制与轻提示 |

## 文档发现

靠 Vite 的 glob 导入完成，一行代码就拿到全部文件内容：

```js
const RAW_DOCS = import.meta.glob('/md/**/*.{md,markdown}', {
  query: '?raw',
  import: 'default',
  eager: true,
});
```

- **开发时**：新增或删除文件会触发页面自动刷新
- **构建时**：内容被打包成静态产物，部署后不需要任何服务器逻辑

## 路径解析

Markdown 里的相对图片、相对链接，都以**当前文件所在目录**为基准解析：

```js
const base = '/md/' + (doc.dir ? doc.dir + '/' : '');
const resolved = new URL(url, new URL(base, location.href));
```

所以 `开发指南/架构设计.md` 里的 `./images/a.png` 会被解析成 `/md/开发指南/images/a.png`。

## 安全边界

Markdown 允许写 HTML，但**渲染前必须过一遍 DOMPurify**：

```js
DOMPurify.sanitize(html, {
  ADD_ATTR: ['target', 'rel', 'data-doc'],
  FORBID_TAGS: ['style', 'script', 'iframe', 'object', 'embed', 'form'],
  FORBID_ATTR: ['style', 'formaction', 'srcdoc'],
});
```

`<details>`、`<kbd>`、`<sub>` 这类安全的 HTML 会保留，
`<script>`、`onerror=`、`javascript:` 这类会被直接剔除。

## 依赖边界

> 能用浏览器原生能力解决的问题，就不引入依赖。

- 目录树、搜索、复制、URL 状态：全部手写，没有路由库、没有状态管理库
- 唯一的三个依赖各司其职：解析、高亮、过滤
